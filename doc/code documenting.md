# code documenting syntax

### **Single-Line Docstring**

- Prefix the object being documented with `///` (triple slash).
- Can span multiple lines if needed.
- Inline explanations can use `//<` for same-line comments.

```E
/// This is a single-line comment
/// (prefixes the object documented, and can be multiline)
let x = 10;  //< explanation in a same line
```

### **Multi-Line Docstring**

- **Prefix Block**: Use `/** ... */` for documentation preceding a code object.
```E
/**
This is a multi-line comment block before some code object
It can span multiple lines.
*/
```

- **Infix Block**: Use `/*! ... */` to document a code block or entire module.

```E
let same x =
/*!
internal documentation about @same
uses @... prefix for code object referencing
*/
	x // returns the same (this comment not goes into docs)
```

### **Key Features**

1. **Explicit Export**:
    
    - Only docstrings with `///`, `/**`, or `/*!` are exported to formal documentation.
    - Regular comments (`//`, `/* */`) are ignored for documentation purposes.
        
2. **Referencing**:
    
    - Use `@symbol` to reference other code objects (e.g., `@same` in the example).
        
3. **Toolchain Support**:
    
    - The [[E/E|E]] toolchain includes [[E/autoformat|autoformatter]] to standardize docstring placement and style.
	- The `doc` generator able to export autogenerated documentation
		- in navigable [[HTML/HTML|HTML]] (dark theme is default)
		- colored navigable [[PDF]] for screen reading
		- gray/color printable [[PDF]] for print-on-demand
